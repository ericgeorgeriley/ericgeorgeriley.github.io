01 / Agentic Software Delivery Framework

Purpose and approach

This framework outlines how we can integrate AI agents into our existing software delivery lifecycle, from customer discussions through to release and support. It is specifically aimed at small development teams where individuals fulfil multiple roles, building on our established tools and processes while maintaining traceable evidence and human approval points for quality, security and control.

Illustrative customer feature

Finance staff need to export completed orders to CSV for a selected date range. The same feature runs from meeting transcripts and reviewed summaries through scope, a UI prototype, implementation, UAT, release and subsequent changes.

Agreed scope Finance users onlyCancelled orders excludedUp to 10,000 rows

Feedback loops are intentional: a UAT defect returns to implementation and verification before the release is authorised. The numbered workflows are capabilities, not mandatory sequential checkpoints.

↶
UAT branch 01 · Already agreed behaviour
Defect: legacy cancelled orders included

The approved baseline already excludes cancelled orders. UAT identifies a defect: fix and reverify it before release, using normal review and CI.

UAT-09 → BUG-021 → PR-141 → reverify → release
↗

Change: add Account Manager column

This was not in REQ-017 and requires CRM data. The request becomes a commercial change and is not included in the current release without approval.

UAT-09 → CR-007 → Commercial approval → Define

03 / BUILD, DEPLOYMENT & INFRASTRUCTURE AS CODE

        
How we build and deploy a project

        
Each project needs a repeatable way to build, test, package and deploy its software. AI helps us write, explain and maintain the automation; normal scripts, CI runners and deployment tools carry out the steps. The implementation depends on the customer's environment. 

      


      

        

          SHARED DELIVERY STANDARDS
          What every release must achieve
          Build successfully, run relevant tests, package consistently and verify the release.
        

        

          PROJECT AUTOMATION
          Scripts and configuration
          Commands and deployment instructions matched to the application's technology and hosting.
        

        

          EXECUTION
          CI and release tools run the steps
          The team uses its existing process to run validated scripts and deploy an approved package.

        Where AI fits: Agents can draft and update the scripts, diagnose failing builds and run permitted checks. The repeatable build and deployment actions are performed by the automation itself, with release timing and access handled through the project's usual process.
      

      
Infrastructure as Code is optional. Where a project provisions its environment using versioned infrastructure definitions, AI can also help maintain and validate those files. This IIS example assumes the server already exists; no IaC is needed for the illustrated release.
